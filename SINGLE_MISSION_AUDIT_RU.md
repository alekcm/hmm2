# Проверка одиночной миссии — 17 октября 2026

## Вывод

**Проект пока не является полным переносом Heroes of Might and Magic V:
Tribes of the East 3.1.** Обещать «не отличить от оригинала» или «без ошибок»
сейчас нельзя. В репозитории есть импортер оригинальных ресурсов и существенный
объём игрового прототипа, но наличие кода не означает, что сценарий проверен
сквозным игровым тестом.

В этой среде нет Unity Editor и C# toolchain. Сборка Unity 6000.6.6f1,
запуск Player, изображение, звук и прохождение миссии **не проверены**.
`ProjectVersion.txt` указывает именно 6000.6.6f1; доступность этой версии и
разрешение Unity-пакетов этой проверкой не подтверждены.

## Что обнаружено и исправлено

### Главное меню и вход в миссию

- Главное меню было дочерним объектом целиком отключаемого HUD. Теперь canvas
  остаётся включённым, а приключенческие панели живут в отдельном `AdventureHUD`.
- `MainMenu.Create` раньше отрисовывал «Import not found» **до** присвоения
  `Database`. База теперь передаётся до построения меню.
- У контейнера меню теперь `RectTransform` на весь canvas; добавлен полноэкранный
  фон, блокирующий клики. Исправлены верхние anchors/высота заголовка.
- Высота содержимого списков рассчитывается по количеству строк: короткие списки
  больше не отодвигают Start далеко вниз, длинные не ограничиваются 2000 px.
- Esc закрывает город или возвращает в главное меню; Resume возобновляет карту.
  В меню отключается контроллер карты, скрывается её корень и не обрабатываются
  приключенческие горячие клавиши. Возврат блокируется во время движения героя
  и боя, чтобы не обрывать корутины движения.
- Continue больше не закрывает меню заранее. Отсутствующий/нечитаемый quicksave
  или отсутствующая карта оставляют сообщение в меню. Проверка наличия карты
  выполняется до восстановления состояния; сохранённый `localPlayerId` передаётся
  в повторную привязку карты.
- Стартовая сцена включена в `EditorBuildSettings`, добавлена её стабильная
  `.meta`. Runtime assembly явно ссылается на `Unity.ugui`.

### Состояние миссии

- Выбор фракции больше не перезаписывается авторской фракцией стартового города:
  игровые данные первого принадлежащего человеку города используют выбранную
  фракцию. Она сохраняется при чтении свежей карты и сериализации сохранения.
  **Внешняя модель города при этом ещё не заменяется.** Это исправление
  состояния построек/экономики, не завершённый визуальный перенос города.
- Нейтральные города больше не раздаются компьютерным игрокам при старте.
  Дополнительные владельцы городов/героев из карты регистрируются в составе
  участников. Сложность передаётся компьютерным участникам.
- При старте матча существующие жилища получают недельный запас для найма;
  после выбора фракции он рассчитывается по её таблицам. Это стартовая логика
  прототипа, не результат сравнения с нативным движком.
- Новая миссия очищает старые гарнизоны, ссылки на объекты и состав игроков.
  Загрузка старого сохранения без списка игроков больше не наследует прошлый матч.
- Выбранный герой материализуется сразу при старте, чтобы немедленное F5
  сохраняло его имя/характеристики до первого открытия экрана героя; пересчитываются
  эффекты навыков и запас маны. Раньше выбор мог оставаться только в несохраняемом кеше.
- Слоты построек копируются, а не разделяют одни и те же изменяемые записи с
  исходным описанием. Живые владелец/тип города синхронизируются с map DTO.
- Выбор случайного города больше не вызывает `Math.Abs(int.MinValue)` для
  соответствующего хеша ID.

## Состояние запрошенных возможностей

| Возможность | Что есть в коде | Что ещё не подтверждено / не завершено |
|---|---|---|
| Главное меню, выбор карты/фракции/героя | `MainMenu`, импорт 64 именных героев, исправления выше | Реальная отрисовка и ввод в Unity; нет оригинального оформления меню |
| Выбранный город | Применение к игровому состоянию первого города игрока | Не меняется внешняя модель; нет оригинального 3D-интерьера; ограничения конкретных сценариев требуют доработки |
| Выбранный герой | Идентичность/характеристики накладываются на первого существующего героя игрока на загруженном этаже | Если такого героя нет, новый не создаётся; стартовая армия/внешняя модель не заменяются полноценным аналогом оригинала |
| Приключенческая карта | Импорт ландшафта/объектов, A*, взаимодействия, этажи, миникарта | Формула стоимости движения упрощена; смешивание ландшафта и материалы неполны |
| Строительство, доход, рост, найм | Таблицы оригинала и `H5TownState`/`TownScreen` | Не все специальные здания и городские механики реализованы |
| Развитие героя | Опыт, навыки/перки, часть эффектов | Неполное соответствие; временная стартовая книга заклинаний ещё присутствует |
| Бой | Пошаговая реконструкция, армии, часть магии, осады и ИИ | Не оригинальная ATB; есть заглушки, например Teleport; не все способности и правила перенесены |
| Музыка/звуки | `H5Audio`, каталог, переключения карта/город/бой/исход | Слышимость, декодирование и переходы в реальном Unity не проверены; часть исходных файлов отсутствует |
| Эффекты заклинаний | `CombatEffects`: снаряды, вспышки, ауры, текстуры оригинала и запасной glow | Это процедурная реконструкция, не перенос всех нативных particle systems |
| Противник/победа | Эвристический `H5AiController`, ход игроков, базовая проверка потери городов/героев | Не оригинальный ИИ; сценарные условия победы, Lua и кампании не перенесены |
| Сохранение/загрузка | JSON состояния мира и участников, исправления выше | Нет проверенного сквозного сохранения/загрузки реальной миссии в Unity |

### В Linux без Unity

```sh
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements-checks.txt
.venv/bin/python -W ignore::ResourceWarning -m unittest discover -s tools/homm5_import/tests -q

.venv/bin/python tools/csharp_access_check.py UnityProject/Assets
.venv/bin/python tools/csharp_call_check.py UnityProject/Assets
.venv/bin/python tools/csharp_name_check.py UnityProject/Assets
.venv/bin/python tools/csharp_type_scope_check.py UnityProject/Assets
```

Результат итогового запуска: **148 тестов, код завершения 0, один пропущен**
(147 успешно выполнены). Четыре C#-анализатора также завершились без находок;
разбор всех 43 C#-файлов tree-sitter не обнаружил синтаксических ошибок.
`git diff --check` прошёл.

Статические анализаторы не заменяют компиляцию: они не проверяют все типы
аргументов, разрешение перегрузок и совместимость Unity API.

Четыре новые Python-проверки проверяют связь GUID скрипта со сценой, включение
стартовой сцены в сборку, зависимость uGUI и подключение PlayMode test assembly.

Пробный запуск всех стадий импортера выполнен с `--limit 1` в отдельный cache:
все семь стадий завершились с кодом 0. `gamedata` вывел полные таблицы
(196 существ, 321 заклинание, 328 построек, 64 героя); каталог звука содержит
2013 эффектов и 155 треков, отмечены 5 отсутствующих исходных звуковых файлов.
Лимит относится не ко всем стадиям: для terrain/maps/meshes/textures/animations
это **выборка по одному ресурсу**, не полный визуальный импорт.

### В Unity — пока НЕ запускались

Добавлены **10 PlayMode-регрессий** в
`UnityProject/Assets/Tests/PlayMode/SingleMissionRegressionTests.cs`:

- холодный bootstrap показывает меню; отсутствующий сценарий не закрывает его;
- скрытие приключенческого HUD не скрывает меню;
- выбор карта → фракция → герой → Start передаёт выбранные ID;
- длинный список карт получает нужную высоту;
- фракция города сохраняется после JSON round-trip и чтения свежей карты;
- слоты построек не изменяют исходные записи по ссылке;
- старт учитывает фракцию/запас найма/сложность и не захватывает нейтральный город;
- выбранный герой попадает в сохранение до открытия его экрана;
- старый save без игроков не наследует прошлый состав;
- новая миссия очищает прошлые города и игроков.

Тесты используют временный синтетический импорт и не трогают пользовательские
сохранения. Запуск: **Window → General → Test Runner → PlayMode → Run All**.
В batchmode (подставить путь к установленному Editor; запускать из корня репозитория):

```sh
mkdir -p .cache
"$UNITY_EDITOR" -batchmode -nographics \
  -projectPath "$PWD/UnityProject" \
  -runTests -testPlatform PlayMode \
  -testResults "$PWD/.cache/unity-playmode.xml" \
  -logFile "$PWD/.cache/unity-playmode.log"
```

## Как запустить прототип с оригинальными ресурсами

1. В корне репозитория выполнить `python import_to_unity.py` (Windows:
   `py -3 import_to_unity.py`). Полный импорт, особенно текстуры, занимает время.
   Сгенерированная папка `UnityProject/Assets/StreamingAssets/HoMM5` не хранится
   в Git; частичный пробный импорт из этой проверки её не заменяет.
2. Открыть `UnityProject` в требуемой версии Unity; дождаться восстановления
   пакетов и импорта. Исправить любые ошибки Console до тестирования.
3. Выполнить PlayMode-тесты выше.
4. Открыть `Assets/Scenes/AdventureMap.unity`, нажать Play. Если Unity отвергнет
   старый YAML сцены — **Tools → HoMM5 → Create Bootstrap Scene** создаст её заново.
5. Проверить вручную: меню → карта с PLAYER_1 и его героем → фракция → герой → Start;
   движение/подбор → город/строительство/найм → бой/магия → конец хода/ИИ →
   F5/F9 → F1 туда и обратно → Esc/Resume. Проверить, что музыка меняется и слышна,
   эффекты видны, ресурсы/армии/постройки сохраняются, Console не содержит ошибок.
6. Для признания переноса точным нужен отдельный набор сравнительных тестов
   с ToTE 3.1: исходы боёв, ATB, движение, экономика, навыки, Lua-условия миссии,
   изображения и звук. Этот этап не выполнен.
